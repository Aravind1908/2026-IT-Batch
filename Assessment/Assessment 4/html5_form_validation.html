HTML5 Form Validation

Using the built-in validation attributes — required, pattern, min, max, minlength, maxlength, and placeholder.

HTML5 · Forms · Validation

1Introduction

Form validation is the process of checking that the data a user enters is correct, complete, and in the right format, before it is submitted and sent to the server. Without validation, a form could accept an empty name, an invalid email, a negative age, or a password that's too short — all of which can break your application.

Validation can be done in two places:

  • Client-side validation — done by the browser as the user types or submits. It gives instant feedback and is fast, but it can still be bypassed, so it is a convenience more than a security guarantee.
  • Server-side validation — done on the server after submission. This is the trustworthy, security-critical validation that must always be performed.

HTML5 makes client-side validation remarkably easy by giving most input elements a set of built-in validation attributes. The browser understands these automatically and stops the form from submitting, showing a helpful message if the data doesn't match. No JavaScript is needed.

2Syntax and its Explanation

Validation attributes are simply added to an <input> or <textarea> tag:

<input
  type="text"
  name="username"
  required
  minlength="3"
  maxlength="15"
  pattern="[A-Za-z0-9]+"
  placeholder="e.g. john_123">

The built-in validation attributes

AttributeWhat it does
requiredThe field must be filled in. The form cannot be submitted empty.
patternChecks the value against a regular expression (regex) before allowing submission.
min/maxSets the smallest / largest allowed value (used with number, date, range, etc.).
minlength/maxlengthSets the minimum / maximum number of characters (for text and textarea).
placeholderShows example hint text inside the field until the user types. (It helps, but does not validate by itself.)
stepFor numeric inputs, sets the valid step (e.g. step="1").
Key rule: These attributes make the browser block submission until the field is valid. However, they are only a convenience — they can be removed by a user, so you must always re-check the data on the server too.

3Features & Uses

Let's look at each attribute in more detail with a practical example.

1. required — the field must not be empty

Adding required means the form won't submit unless the field has a value.

<input type="email" name="email" required>

2. pattern — enforce a specific format with regex

Validates against a regular expression. Below, the password must contain at least one number and one letter, with 8+ characters.

<input type="password" name="password" pattern="(?=.*\d)(?=.*[A-Za-z]).{8,}" title="At least 8 chars with a letter and a number">

3. min / max — set the allowed value range

For numbers and dates. The value must be at least min and at most max.

<input type="number" name="age" min="18" max="99" required>

4. minlength / maxlength — limit the character count

For text and textarea. maxlength physically stops extra characters from being typed; minlength blocks submission if there are too few.

<input type="text" name="username" minlength="4" maxlength="20">

5. placeholder — helpful example text

Displays a hint inside the field. It is a guide, not a validation rule — it disappears as soon as the user types.

<input type="tel" name="phone" placeholder="e.g. 98765 43210">
Did you know? When a field fails validation, the browser automatically shows an error bubble. You can give clearer feedback by adding a title attribute to the field — it appears in that message.

4Example Programs with Explanation

Example 1 — A sign-up form with validation attributes

This form uses everything: required, pattern, min/max, minlength/maxlength, and placeholder. Try to submit it with empty, too-short, or badly-formatted values to see the browser block it.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Sign Up Form</title>
</head>
<body>

<form action="signup.php" method="post">

  <!-- required + placeholder -->
  <label for="name">Name (required):</label>
  <input type="text" name="name" placeholder="Vijay Kumar" required><br>

  <!-- email is auto-validated by the browser -->
  <label for="email">Email:</label>
  <input type="email" name="email" required><br>

  <!-- minlength/maxlength + pattern -->
  <label for="user">Username (4-15, letters/numbers):</label>
  <input type="text" name="username"
         minlength="4" maxlength="15"
         pattern="[A-Za-z0-9]+" required><br>

  <!-- min/max for numbers -->
  <label for="age">Age (18-99):</label>
  <input type="number" name="age" min="18" max="99"><br>

  <!-- min/max for dates -->
  <label for="dob">Date of Birth:</label>
  <input type="date" name="dob" min="1930-01-01" max="2008-12-31"><br>

  <!-- textarea with minlength/maxlength -->
  <label for="bio">Bio (10-200 chars):</label><br>
  <textarea name="bio" rows="4" minlength="10" maxlength="200"></textarea><br>

  <button type="submit">Sign Up</button>
</form>

</body>
</html>
Explanation of Example 1:
  • required — the name, email, and username must be filled in.
  • type="email" — the browser checks the email format automatically.
  • minlength="4" / maxlength="15" — the username must be 4 to 15 characters; typing past 15 is blocked.
  • pattern="[A-Za-z0-9]+" — the username may only contain letters and numbers (no spaces or symbols).
  • min="18" / max="99" — age must be in that range.
  • min / max on the date — restricts birth dates to a sensible period.
  • placeholder — shows hints like "Vijay Kumar" and "e.g. 4-15 chars".

Example 2 — Pattern validation for a phone number

This example focuses on the pattern attribute. It ensures the user enters a valid Indian mobile number format, and uses title to give a clear error message when the format doesn't match.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Pattern Validation</title>
</head>
<body>

<h3>Contact Details</h3>
<form action="contact.php" method="post">

  <!-- pattern for a 10-digit Indian mobile number -->
  <label for="mobile">Mobile Number (10 digits):</label>
  <input type="tel" name="mobile"
         pattern="[6-9][0-9]{9}"
         title="Please enter a 10-digit number starting with 6, 7, 8, or 9"
         placeholder="9876543210" required><br>

  <!-- minlength/maxlength on a pin code -->
  <label for="pincode">PIN Code:</label>
  <input type="text" name="pincode"
         pattern="[0-9]{6}" title="6-digit PIN code"
         placeholder="600001" required><br>

  <button type="submit">Submit</button>
</form>

</body>
</html>
Explanation of Example 2:
  • pattern="[6-9][0-9]{9}" — requires a 10-digit number; the first digit must be 6, 7, 8, or 9 (as Indian mobile numbers do).
  • title="..." — the text shown in the browser's error bubble if the pattern fails.
  • pattern="[0-9]{6}" — for the PIN code, requires exactly 6 digits.
  • required — ensures neither field can be left empty.
  • placeholder — shows example values like "9876543210".
How to try it
Copy either example into a file named index.html and open it in a browser. Try leaving a field empty, typing an invalid email, a short username, an age of 10, or a bad phone number — then press Submit. The browser will block submission and show a message explaining what's wrong (thanks to title). Note that no data is actually sent anywhere without a server.

5Advantages

  • Instant feedback: The browser tells the user what's wrong immediately, without waiting for the server.
  • No extra code: Built-in attributes handle most validation with pure HTML — no JavaScript needed.
  • Better data quality: Prevents empty fields, wrong formats, and out-of-range values from reaching the server.
  • Improved user experience: Users get guided, clear error messages; the correct keyboard appears (email, numbers, date).
  • Lightweight & fast: Validation happens in the browser, reducing round-trips to the server.
  • Works with accessibility: Screen readers announce validation errors, helping all users.

6Conclusion

HTML5 form validation gives us a simple, no-JavaScript way to make sure the data a user submits is complete and correct. With attributes like required, pattern, min/max, minlength/maxlength, and placeholder, the browser itself enforces the rules and gives clear feedback.

In summary: use these attributes to catch obvious mistakes early and guide the user, but always validate again on the server. Client-side validation is about convenience and experience; server-side validation is about correctness and security. Combine them, and your forms will be both easy to use and safe. As the saying goes: "Validate for the user, then validate for the server."
