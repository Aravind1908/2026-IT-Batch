Browser DevTools & Emmet

Short notes on Developer Tools — Elements, Console, Network, device emulation — and Emmet abbreviations with examples.

DevTools · Emmet · Productivity

1Introduction

Browser DevTools (Developer Tools) are a set of debugging and inspection tools built right into every modern browser. They let you view and edit the live HTML, run JavaScript, watch network requests, and simulate different screen sizes — all without changing your actual files. Access them by pressing F12 or by right-clicking anywhere and choosing Inspect.

Emmet is a productivity tool (a plugin/shortcut engine) that writes HTML and CSS for you. You type a short abbreviation and press Tab, and Emmet expands it into full, correctly-nested code. It comes built into VS Code, and is also available for most editors.

Together they form the everyday toolkit of a front-end developer: DevTools to inspect and debug, Emmet to write code faster. Both save enormous time and are worth mastering early.

Key rule: DevTools edits are temporary — they update the live page but do not save to your files. Emmet, on the other hand, writes real code into your editor which you then save.

3Features & Uses

1. Elements tab — inspect & edit HTML/CSS

Shows the DOM tree of the page. Click any element to see its styles in the "Styles" pane and its dimensions in the "Computed"/box-model view. You can edit HTML and CSS live to test changes instantly.

// Useful things you can do in the Elements tab:
- Inspect any element (Hover highlights it in the page)
- Edit text and attributes directly
- Change CSS properties in real time
- Toggle styles on/off with checkboxes

2. Console tab — JavaScript & logs

A place to run JavaScript and read logs/errors. Use console.log() in your code to print messages here, and type expressions directly to test them.

// Try these in the Console:
2 + 3          // => 5
document.title   // => text of the title
console.log("Hello") // prints Hello

3. Network tab — see every request

Lists all files the page loads (HTML, CSS, JS, images, API calls). It shows size, timing, status (200, 404), and lets you filter by type. This is how you discover slow or failing resources.

// How to use it:
1. Open the Network tab
2. Reload the page (Ctrl+R)
3. Click any request to see headers, preview, & timing

4. Device emulation — responsive testing

Lets you view and test how your page looks on different devices — phones, tablets, desktops. Use the "toggle device toolbar" button (or press Ctrl+Shift+M). It simulates screen sizes and touch, so you can test responsiveness without a real phone.

// Steps:
1. Click the device-toolbar icon (a phone/tablet icon)
2. Choose a device preset (e.g. iPhone, Pixel)
3. Pick a width, orientation, even a network throttle

Emmet — write code fast

Type an abbreviation and press Tab. Here are some common ones in practice:

// Type this ...  and press Tab
ul>li*3                // A ul with 3 list items
div.container          // A div with class "container"
a                    //        -> <a href=""></a>
form>label+input       //        -> form with label then input
Did you know? Emmet also speeds up CSS. For example, typing m10 then Tab gives margin: 10px;, and df gives display: flex;. In VS Code it's built in — try it!

4Example Programs with Explanation

Example 1 — Emmet abbreviations expanded to HTML

This shows the abbreviation on the left and the real HTML it expands to on the right. In the editor, you type only the abbreviation and press Tab.

// Abbreviation:  ul>li.item*3
<ul>
  <li class="item"></li>
  <li class="item"></li>
  <li class="item"></li>
</ul>

// Abbreviation:  table>tr>td*3   ->  a 3-column table row
<table><tr><td></td><td></td><td></td></tr></table>

// Abbreviation:  header.nav>a*3
<header class="nav">
  <a href=""></a><a href=""></a><a href=""></a>
</header>
Explanation of Example 1:
  • ul>li.item*3 creates a <ul> containing three <li class="item"> children.
  • table>tr>td*3 builds a table with one row of three columns.
  • header.nav>a*3 makes a <header class="nav"> with three anchor links inside.
  • The > means "child", the *n means "repeat n times", and a class is written with a dot.

Example 2 — A small page to test in DevTools

This is a simple page you can inspect. Open it in your browser, then practice with Elements (edit a style), Console (run a command), Network (see what loads), and device emulation (make it look like a phone).

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>DevTools Practice</title>
  <style>
    body  { font-family: Arial, sans-serif; margin: 20px; }
    .box  { padding: 20px; background: #fdeadb; border: 2px solid #b45309; }
    #main { max-width: 600px; margin: auto; }
  </style>
</head>
<body>
  <div id="main">
    <h1 class="title">Hello DevTools!</h1>
    <div class="box">Inspect this box.</div>
  </div>
</body>
</html>
Explanation of Example 2:
  • Elements: Select the .box and change background to a new colour — it updates live.
  • Console: Type document.title and press Enter — it shows "DevTools Practice".
  • Network: Reload and watch the single HTML request appear.
  • Device emulation: Turn on the device toolbar to see the layout shrink to phone width (thanks to the viewport meta tag).
How to try it
Save Example 2 as index.html and open it. Press F12, then explore each tab. For Emmet, open any code editor (like VS Code), type ul>li*3 and press Tab to see it expand.

5Advantages

  • Instant debugging: See exactly what the browser is doing and fix issues without guessing.
  • Test changes live: Edit HTML/CSS directly and preview the result instantly.
  • Responsive testing: Device emulation lets you check mobile layouts without an actual phone.
  • Performance insight: The Network tab reveals slow, large, or failing resources.
  • Faster coding with Emmet: Abbreviations generate nested HTML/CSS in seconds, reducing typing mistakes.
  • Cross-device, cross-browser: DevTools work the same across Chrome, Edge, Firefox, and more.

6Conclusion

Browser DevTools and Emmet are two time-savers every web developer should know. DevTools — especially the Elements, Console, Network, and device emulation tools — let you inspect, debug, and test your site live, so you can see exactly why a page behaves the way it does. Emmet, meanwhile, turns short abbreviations into full, correct HTML and CSS, so you write less and make fewer mistakes.

In summary: use DevTools to understand and fix your page, and use Emmet to build it faster. Together they help you ship better websites with less effort. As the saying goes: "Inspect, experiment, and let the tools do the typing."
