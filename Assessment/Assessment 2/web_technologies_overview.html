Overview of Web Technologies

Understanding the two halves of the web — client-side vs. server-side — and the roles of HTML, CSS, and JavaScript.

Frontend · Backend · The Web

1Introduction

Every website you have ever visited is a collaboration between two "sides" of the web. When you open a web page, your browser (the client) sends a request to a computer (the server) that holds the website's files. The server responds with those files, and your browser then builds the page you see on your screen.

This flow gives us two broad categories of web technology:

  • Client-side (front-end) — the code that runs in your browser. It is what you see and interact with: layout, colors, buttons, animations.
  • Server-side (back-end) — the code that runs on the server. It is invisible to you but does the "heavy lifting": reading databases, checking passwords, processing payments, and generating the content the browser needs.

On the client side, three core technologies work together: HTML builds the structure, CSS controls the appearance, and JavaScript adds interactivity. You can think of a website as a house — HTML is the bricks and walls, CSS is the paint and furniture, and JavaScript is the electricity and plumbing that make it "work."

2Syntax and its Explanation

Each core web technology has its own small, simple syntax. Here is a quick look at the three client-side languages, plus a peek at how the client/server split works.

HTML — the structure

<!-- Tags wrap content. Most have an open & closing tag -->
<h1>Hello, World!</h1>
<p>This is a paragraph.</p>
<img src="photo.jpg" alt="A photo"> <!-- self-closing -->

CSS — the style

/* Selector { property: value; } */
h1 { color: blue; font-size: 24px; }

JavaScript — the behaviour

// Variables, functions, and events
let name = "Aisha";
function greet() { alert("Hello " + name); }

Client-side vs. Server-side at a glance

Where it runsIn the user's browserOn the web server
What the user seesYes — directly visibleNo — invisible

Key rule: These two sides always talk to each other. The client asks the server for data, and the server sends back an answer. A complete website normally combines both — no modern site is just HTML alone.

3Features & Uses

Let's look at what each technology is actually good at, and how the two sides divide up the work of a real website.

HTML — the structure (skeleton)

Defines the content and meaning of a page: headings, paragraphs, images, links, lists, forms. It tells the browser what each thing is.

<h1>Title</h1>
<ul><li>Item</li></ul>

CSS — the style (appearance)

Controls how the content looks: colors, fonts, spacing, layout, and responsiveness. Keeps design separate from content.

body { background: #fff; }
p   { color: gray; }

JavaScript — the behaviour (interactivity)

Adds dynamic behaviour: responding to clicks, validating forms, making API calls, and updating the page without a full reload.

btn.addEventListener("click", () => { btn.style.color = "red"; });

Server-side — the brain

Handles data, security, and logic: storing records, authenticating users, sending emails, and computing results you can't (or shouldn't) do in the browser.

const user = findUser(username);
if (user.password === entered) { login(); }
Did you know? A single page can contain all three client-side languages, plus a server that supplies the data. Because the client and server are separate, a website can keep working (the page still shows) even if the server's data is slow to arrive.

4Example Programs with Explanation

Example 1 — A complete client-side page (HTML + CSS + JS combined)

This example is a small interactive page that uses all three client-side technologies in one file: HTML builds the structure, CSS styles it, and JavaScript makes a button change the page when clicked.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Interactive Page</title>
  <style>
    body { font-family: Arial; text-align: center; }
    button { padding: 10px 20px; }
  </style>
</head>

<body>
  <h1 id="title">Click the button!</h1>   <!-- HTML structure -->
  <button id="btn">Click Me</button>

  <script>
    document.getElementById("btn").addEventListener("click", function() {
      document.getElementById("title").innerText = "You changed me!";
    });
  </script>
</body>
</html>
Explanation of Example 1:
  • HTML — creates the structure: a heading and a button.
  • CSS — styles the page: font, centered text, and button padding.
  • JavaScript — listens for a click on the button and updates the heading text to "You changed me!". This interactivity happens entirely in the browser, so no server is involved.

Example 2 — A simple server-side example (PHP)

This example shows the server side working. A PHP script runs on the server, reads the current time, and builds HTML that gets sent to the browser. The user never sees the PHP code — only the HTML it produces.

<?php // This part runs on the SERVER -->
<?php
  $name = "Aisha";                 // server-side data
  $hour = date("H");              // current hour on server
  if ($hour < 12) { $greeting = "Good morning"; }
  else { $greeting = "Good afternoon"; }
?>

<!-- The browser only ever receives the HTML below -->
<!DOCTYPE html>
<html>
  <body>
    <h1><?php echo $greeting . ", " . $name; ?></h1>
  </body>
</html>
Explanation of Example 2:
  • The <?php ... ?> block runs on the server before the page is sent.
  • It creates a variable $name, reads the server's current hour, and decides between "Good morning" and "Good afternoon".
  • The server then produces a plain HTML page with the greeting filled in, and sends it to the browser. The browser never sees the PHP — it only sees the resulting HTML. This is the key difference from client-side code.
How to try it
For Example 1, save it as index.html and open it in a browser — click the button to see the change. For Example 2, you need a server that runs PHP (like XAMPP, WAMP, or an online PHP playground) and save it as index.php.

5Advantages

  • Clear division of work: Splitting client and server keeps each side focused, simple, and easier to maintain.
  • Better user experience: Client-side code responds instantly to clicks without waiting for the server, making pages feel fast and smooth.
  • Security & control: Sensitive logic (passwords, payments, data) stays on the server, out of reach of the user's browser.
  • Separation of concerns: HTML (structure), CSS (style), and JS (behaviour) keep code clean, reusable, and easy for teams to work on independently.
  • Reusable & scalable: The same front-end can talk to many different back-ends, and vice versa, so systems can grow easily.
  • Accessible & indexable: Semantic HTML and server-rendered content work well for screen readers and search engines.

6Conclusion

Understanding the web as two connected halves — the client (your browser) and the server — is the foundation of all web development. The client side, built from HTML, CSS, and JavaScript, is responsible for everything the user sees and touches. The server side, built from languages like PHP, Python, or Node.js, is responsible for the data, security, and logic that make a site genuinely useful.

In summary: HTML provides the structure, CSS provides the style, and JavaScript provides the behaviour — all running on the client. The server supplies the behind-the-scenes power. A real-world website combines both sides working together in a constant exchange of requests and responses. Master this mental model, and every other concept in web development will fall into place. Quoting the common phrase: "The client shows, the server knows."
