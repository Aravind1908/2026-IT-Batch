Structure of an HTML5 Table

A complete guide to building tables with thead, tbody, tfoot, caption, colspan, and rowspan.

HTML5 · Tables · Layout

1Introduction

A table is the standard way to present data in rows and columns — like a timetable, a price list, a comparison chart, or a result sheet. HTML5 gives us a rich set of tags to build tables that are well-structured, readable, and accessible.

Before HTML5, tables were even abused for page layout. Today we use CSS for layout, and tables are used properly — for tabular data. A well-built table should separate its structure into logical parts so that browsers, search engines, and screen readers all understand it.

HTML5 tables are built around a few key elements:

  • <table> — the container for the whole table.
  • <caption> — a title/description for the table.
  • <thead> — the header row(s) at the top.
  • <tbody> — the main body of data rows.
  • <tfoot> — the footer row(s) at the bottom (e.g., totals).
  • <tr> — a single row.
  • <th> — a header cell (bold by default).
  • <td> — a regular data cell.
  • <colspan> / <rowspan> — attributes that merge cells.

2Syntax and its Explanation

The general skeleton of an HTML5 table looks like this:

<table>
  <caption>Table Title</caption>

  <thead>
    <tr>
      <th>Column A</th>
      <th>Column B</th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>Data 1</td>
      <td>Data 2</td>
    </tr>
  </tbody>

  <tfoot>
    <tr>
      <td>Total</td>
      <td>Sum</td>
    </tr>
  </tfoot>
</table>

Cells: <th> vs <td>

ElementMeaningAppearance
<th>A header cell — labels a row or column.Bold and centered by default.
<td>A standard data cell.Regular text, left-aligned by default.
<tr>A table row.Holds one or more cells.

Merging cells: colspan and rowspan

Sometimes a cell needs to span more than one column or row.

<!-- colspan: this cell stretches across 3 columns -->
<th colspan="3">Annual Report</th>

<!-- rowspan: this cell stretches down 2 rows -->
<td rowspan="2">Label</td>
AttributeWhat it doesDirection
colspanMakes a single cell span multiple columns (horizontally).Across →
rowspanMakes a single cell span multiple rows (vertically).Down ↓
Key rule: A table should contain one <caption>, one <thead>, one (or more) <tbody>, and one <tfoot>. The header (<thead>) should come before the body (<tbody>) in the code, even though the footer (<tfoot>) is visually at the bottom.

3Features & Uses

Here is what each table feature does, with a small example for each.

1. <caption> — a title for the table

Gives the table a visible title/description. It is a great accessibility feature because it tells a screen reader what the table is about.

<caption>Monthly Sales Report</caption>

2. <thead> — the header row(s)

Wraps the top row that labels the columns. It is useful for styling (e.g., a colored header) and for repeating on each printed page.

<thead>
  <tr><th>Product</th><th>Price</th></tr>
</thead>

3. <tbody> — the data rows

Groups the actual data rows. This is the main section of any table.

<tbody>
  <tr><td>Laptop</td><td>$999</td></tr>
  <tr><td>Mouse</td><td>$29</td></tr>
</tbody>

4. <tfoot> — the summary/footer rows

Holds summary rows like totals or averages. In the HTML it is placed after the <tbody> in source order, though browsers display it at the bottom.

<tfoot>
  <tr><td>Total</td><td>$1028</td></tr>
</tfoot>

5. colspan — merge across columns

Useful for a header spanning several columns or a cell that groups data.

<th colspan="2">Product Details</th>

6. rowspan — merge down rows

Useful when one value applies to several rows, like a category label spanning many items.

<td rowspan="3">Electronics</td>
Did you know? Modern tables use the semantic parts (<thead>, <tbody>, <tfoot>) for the same reason we use <header>/<main>/<footer> in page layout — they make the structure understandable to browsers, search engines, and assistive technology.

4Example Programs with Explanation

Example 1 — A basic table with thead, tbody, tfoot, and caption

This example builds a simple table showing products and prices, with a header row, three data rows, a footer total, and a caption title. It uses all five main structural tags in one table.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <style>
    /* thin borders to make the table clear */
    table, th, td { border: 1px solid #ccc; border-collapse: collapse; padding: 8px; }
    th { background: #fdecdd; }
  </style>
</head>
<body>

  <table>
    <caption>Product Price List</caption>

    <thead>
      <tr>
        <th>Product</th>
        <th>Quantity</th>
        <th>Price</th>
      </tr>
    </thead>

    <tbody>
      <tr><td>Laptop</td><td>1</td><td>$999</td></tr>
      <tr><td>Mouse</td><td>2</td><td>$58</td></tr>
      <tr><td>Keyboard</td><td>1</td><td>$45</td></tr>
    </tbody>

    <tfoot>
      <tr>
        <td colspan="2">Total</td>
        <td>$1102</td>
      </tr>
    </tfoot>
  </table>

</body>
</html>
Explanation of Example 1:
  • <caption> gives the table the title "Product Price List".
  • <thead> holds the header row with column labels (Product, Quantity, Price).
  • <tbody> contains the three data rows.
  • <tfoot> holds the total row at the bottom.
  • colspan="2" makes the "Total" label span the first two columns, so it lines up neatly with the price column.

Example 2 — Using colspan and rowspan to merge cells

This example shows a more complex table with merged cells. rowspan combines multiple rows under one category, and colspan combines columns for a heading and a full-width note.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <style>
    table, th, td { border: 1px solid #ccc; border-collapse: collapse; padding: 8px; text-align: center; }
    th { background: #fdecdd; }
  </style>
</head>
<body>

  <table>
    <caption>Store Inventory by Category</caption>

    <tr>
      <th colspan="3">Available Items</th>
    </tr>
    <tr>
      <th>Category</th>
      <th>Item</th>
      <th>Stock</th>
    </tr>

    <!-- rowspan spans 2 rows for the "Electronics" category -->
    <tr>
      <td rowspan="2">Electronics</td>
      <td>Laptop</td>
      <td>10</td>
    </tr>
    <tr>
      <td>Phone</td>
      <td>25</td>
    </tr>

    <!-- rowspan spans 2 rows for the "Furniture" category -->
    <tr>
      <td rowspan="2">Furniture</td>
      <td>Chair</td>
      <td>40</td>
    </tr>
    <tr>
      <td>Table</td>
      <td>12</td>
    </tr>

    <!-- colspan spans all 3 columns for a full-width note -->
    <tr>
      <td colspan="3">Total items in stock: 87</td>
    </tr>
  </table>

</body>
</html>
Explanation of Example 2:
  • colspan="3" on the top row merges all three columns into a single heading "Available Items".
  • rowspan="2" on the "Electronics" cell makes the category label span the two rows below it (Laptop, Phone). The second row (Phone) therefore needs no separate Category cell.
  • The same rowspan="2" idea is used for "Furniture" (Chair, Table).
  • The last colspan="3" creates a full-width summary line across the entire table.
How to try it
Copy either example into a file named index.html and open it in a browser. You'll see the borders make the structure obvious. To really understand rowspan/colspan, try changing the numbers and observe how the grid reflows.

5Advantages

  • Clear data presentation: Perfect for showing data that belongs in rows and columns, like reports and comparisons.
  • Better accessibility: <caption>, <th>, and the row/column structure let screen readers present data in an understandable way.
  • Improved SEO: Well-structured tables are easier for search engines to read and interpret.
  • Semantic & readable code: <thead>, <tbody>, and <tfoot> make the purpose of each section obvious.
  • Flexible layout: colspan and rowspan let you merge cells to create a clean, professional grid.
  • Reusable & styleable: Tables work easily with CSS, so you can style headers, rows, or zebra-stripe the body.

6Conclusion

Tables are the natural way to present relational data, and HTML5 gives us the tools to build them with clear structure and meaning. A well-constructed table includes a <caption>, a <thead> for the header labels, a <tbody> for the data, and a <tfoot> for summaries — and uses colspan and rowspan to merge cells wherever a value spans multiple columns or rows.

In summary: use semantic tags to define the purpose of each part of the table, and colspan/rowspan to control how cells combine. This makes your data readable for everyone — sighted users, screen-reader users, and search engines alike. As the rule of thumb goes: "Use tables for data, not for layout — and always give them structure."
